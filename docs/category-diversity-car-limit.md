# 일정 카테고리 반복 감점과 자가용 구간 제한

사용자 요청에 따라 같은 날의 카테고리 반복을 소프트 감점하고, 자가용 여행지 간 한 구간을 최대 40분으로 제한한다. 이번 후속은 로컬 구현·검사·커밋만 수행하며 원격 push·PR·Notion을 갱신하지 않는다. 회피 문장과 도보 파싱은 이번 변경 범위가 아니다.

## 카테고리 감점

- 범위는 같은 날짜의 유연한 방문이다. 다른 날짜의 같은 카테고리는 함께 감점하지 않는다.
- 이미 검증된 후보의 기존 최저 개인 점수→단체 평균 순위를 기본 효용으로 사용한다. 같은 카테고리의 양의 효용을 큰 순서로 정렬해 첫 방문은 그대로, 두 번째는 1/2, 세 번째는 1/3처럼 줄인다. 입력 순서만 바꿔 점수가 달라지지 않는다. 점수는 내부 선택 기준이며 사용자 만족도 측정값이 아니다.
- 실제 카탈로그의 `contenttypeid`/`contentTypeName`을 사용하고, 없으면 알려진 `planningRole`을 사용한다. 정확한 카탈로그 `카페` 태그가 있을 때만 카페를 별도 분류한다. 장소 이름에서 세부 분류를 추측하지 않는다. 미상 카테고리를 하나로 묶지 않는다.
- DB에 세부 분류가 없으면 관광지·음식점 같은 넓은 범주로 감점된다. 박물관 등 모든 세부 종류가 구분된다는 의미가 아니다.
- 고정 예약과 숙소는 감점에서 제외한다. 식사는 삭제하지 않고 식사 후보 사이에서만 대체한다. 식사와 숙박을 다른 날짜로 옮겨 다양성 점수를 높이지 않는다. 관광·문화·체험·쇼핑 등 유연한 방문은 적격 후보 안에서 대체할 수 있다. 선호 순위가 조금 낮더라도 반복 감점 후 더 좋은 조합이면 검토한다.
- 감점은 중복 금지가 아니다. 후보 부족·높은 선호·필수 제약 때문에 같은 카테고리가 남을 수 있다. 허용 날짜, 식사·예약·숙소, 도보·시간·영업시간·알려진 예산과 미확인 악화를 재검사한다.

## 자가용 40분

- 실제 경로 시간이 있는 `car`의 `PLACE → PLACE`에 적용한다. 숙소에서 다음 날 첫 여행지로 가는 구간도 포함한다.
- 집·출발지 `START → 첫 장소`, `마지막 장소 → END`는 제외한다. 방문 목록에 들어 있는 실제 장소끼리라면 같은 제한을 적용한다.
- 원시 초를 기준으로 **2400초는 허용, 2401초는 초과**다. 거리(km) 상한은 추가하지 않는다. 도보·대중교통에 자동차 제한을 적용하지 않는다.
- 알려진 초과 구간은 일정 맞춤 단계에서 가능한 유연 방문을 조정한다. 고정 예약·숙소를 삭제하거나 시간을 40분으로 잘라 쓰지 않는다. 해결 불가능하면 생성 실패 또는 위반 초안으로 남기고 정상 저장을 막는다.
- 조회 실패·시간 초과·좌표 미상은 기존 미확인 상태다. 시간표 작성을 위한 30분 가정이 ‘40분 이내 검증’으로 바뀌지 않는다. 기존 미확인 확인 후 저장 규칙과 실제 검증 완료를 구분한다.

## 기존 일정과 호환성

비공개 생성 source token에 `GENERATION_POLICY_VERSION`을 포함한다. 이전 정책으로 만든 성공 작업과 일정은 최신 정책의 결과로 재사용하지 않으며, 이전 초안의 저장은 stale 검사로 막는다. 과거 데이터를 삭제·변환하지 않는다. 서버를 재시작한 뒤 기존 일정은 다시 생성해야 새 정책을 적용받는다.

새 endpoint·공개 DTO·DB 컬럼·migration·의존성·CI는 추가하지 않는다. 카테고리 키와 감점 진단은 내부 데이터다. 기존 총 64회 경로 조회·일정 검증 시간 한도와 최적화 24회 평가·추가 경로 최대 6회 한도를 유지한다.

## 검증 범위

합성 후보·가짜 방향성 이동시간·SQLite로 감점, 실제 후보 교체, 40분 경계, 출발·복귀 예외, 숙소 연결, 수리 가능/불가능, 미확인·저장 차단과 정책 버전 변경을 확인한다. 실제 Gemini/Kakao 호출이나 공용 DB 테스트를 이 검사로 주장하지 않는다. 기존 [AI 평가 결과](ai-quality-evaluation-results.md)는 이전 정책의 개발 평가 기록이며 새 정책의 실사용 효과를 뜻하지 않는다.

- 실제 Gemini/Kakao·브라우저·공용 DB 쓰기·전용 MySQL 통합 검사는 수행하지 않았다. 로컬 전용 요청에 따라 push·PR·Notion 변경은 하지 않았다. 기존 회피 문장 해석 코드는 변경하지 않았다.
