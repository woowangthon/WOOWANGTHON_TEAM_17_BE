# API 작업: FE가 명세 작성, BE가 구현

현재 API 규격 원본은 [Notion API 계약 페이지](https://app.notion.com/p/40ee977e49088030a073ffd13d06c144)다.

## 기본 흐름

1. **FE가 확인한다.** 기능에 필요한 API를 Notion에서 찾아 기존 규격을 재사용한다.
2. **FE가 작성한다.** 없거나 부족하면 기능에 맞는 method/path, 요청·응답 예시, 인증·권한, 오류를 정해 Notion에 작성한다. 작성이 끝나면 해당 항목을 **구현 요청**으로 표시한다.
3. **BE가 구현한다.** 구현 요청 항목과 [DB 구현 기준](database-schema.md)의 관련 테이블을 읽고 그 규격대로 구현·검증한다. API 필드를 기존 컬럼·JSON·관계에 매핑하고 DB 제약과 충돌하는 부분만 확인한다. 별도 FE·BE 이중 승인이나 계약 승인 대기를 공통 절차로 두지 않는다.
4. **FE가 연결한다.** BE가 구현 결과와 실제 검증 결과를 남기면 FE가 mock을 실제 API 호출로 바꾸고 화면 동작을 확인한다.

작성 중 / 구현 요청 / 구현 완료만 구분하면 된다. FE의 구현 요청은 규격 작성이 끝났다는 의미이며 BE 구현 완료를 뜻하지 않는다. BE는 실제 구현과 검증을 마친 범위만 구현 완료로 보고한다.

## 역할 경계

- **FE:** 규격 본문 작성·수정, 기존 API 재사용과 화면 요구 확인. 기존 호출을 깨는 변경은 영향받는 화면과 BE에 변경 내용을 공유한다. 여러 FE 작업이 겹치면 같은 API의 작성자를 한 명으로 정한다.
- **BE:** 명세 읽기, 구현·검증, 구현 상태와 관련 BE PR 링크 기록. 명세에 없는 제품 동작·인증/권한을 지어내거나 규격을 임의로 바꾸지 않는다. 빠진 내용·모순·구현 불가능한 조건·보안상 문제가 있을 때만 해당 부분을 FE에 확인한다. 독립 작업은 계속한다.
- 각 레포의 root가 관련 Notion 조회/쓰기를 맡고 하위 역할에는 필요한 명세를 전달한다. BE에서 새 기능 요청을 받아도 규격이 없으면 필요한 내용을 FE에 전달하고 임의로 새 API 규격을 확정하지 않는다.

기능 요청 범위의 Notion 명세 작성(FE) 또는 구현 상태·PR 링크 갱신(BE)은 기본 작업에 포함한다. 읽기 전용·로컬 전용 또는 개별 쓰기 제한은 사용자 지시를 우선한다. BE가 읽기만 하도록 요청받았다면 상태·링크도 쓰지 않는다.

## 명세 양식과 변경

기능명, 상태, HTTP method/path, 인증·권한, 요청 필드와 예시, 성공 응답 예시, 오류 응답, 특이사항, 관련 FE/BE PR이면 시작할 수 있다. API ID·개정 번호·양쪽 승인자 필드를 필수로 요구하지 않는다. 단위·nullable·시간대·동시성 등은 해당 기능에서 필요한 만큼 명시한다.

BE는 작업 시작 시 구현 요청 명세를 읽는다. 작업 도중 명세가 바뀌면 FE에 변경 의도를 확인하고 영향받는 구현·검증만 갱신한다. 구현 완료 보고 전에는 관련 명세와 결과를 대조한다. 별도 네 번 재확인 절차를 강제하지 않는다.

PR에는 관련 Notion 페이지, 구현한 method/path, 사용한 명세의 핵심 내용·변경 요약, 실제 검사 결과를 남긴다. 과거 내용 재현이 필요하면 관련 본문을 PR/문서에 인용할 수 있지만 별도 스냅샷 파일이나 버전 관리 체계는 필수가 아니다. FE/BE의 Git 이슈·브랜치·커밋·PR은 각각 관리하고 관련 PR을 서로 연결한다. 사람만 병합한다.

## 연결 실패와 현재 준비 상태

Notion을 읽을 수 없거나 본문이 누락됐으면 API가 없다고 단정하지 않는다. 읽기·쓰기 실패를 보고하고 확인 가능한 독립 작업만 계속한다. 쓰기 결과가 불확실하면 먼저 조회해 중복 작성을 막고, 다른 항목·하위 페이지를 보존한다.

DB 구조는 사용자 제공 Dump20261104.sql의 24개 테이블을 [스키마 DDL 참조](database-schema-reference.md)에 기록했다. DB 구조는 이미 있으므로 임의 재설계하지 않는다. 다만 BE 앱·OpenAPI·DB 연결은 아직 없고 Python 버전·ORM·인증·실행/검사 명령도 미정이다. 실제 설정된 도구만 쓴다. 향후 /docs와 /openapi.json은 FastAPI 기본 경로 예시이며 실제 설정을 확인한다. OpenAPI만으로 실제 권한·오류·DB 동작의 검증이 끝나지는 않는다.

이 규칙은 요청할 때 Codex가 Notion을 읽고 작업하는 방식이다. FE가 Notion에 적었다는 이유만으로 BE가 자동 실행되지는 않는다. BE 채팅에서 구현을 요청해야 한다. watcher·양방향 자동 동기화·FE 타입 자동 갱신은 구성하지 않는다.
