# 일반 식사 시간의 권장화

일반 점심·저녁 시간대는 생성의 권장 기준으로 사용한다. 사용자가 확정한 식사·예약 시각은 기존 필수 앵커로 보존한다. 이 변경은 로컬 전용이며 지역 후보 처리, 취향 해석·확정, 생성 실패 안내, FE, 공개 API·DB 구조를 수정하지 않는다.

## 시간표와 최적화

자동 식사를 점심 11:30, 저녁 17:30까지 강제로 기다리게 하지 않는다. 점심 14:30, 저녁 20:00이라는 권장 구간을 벗어났다는 이유만으로 장소를 삭제하거나 생성을 실패시키지 않는다. 새로운 고정 대기시간도 추가하지 않는다.

활동 종료, 식당의 확인 가능한 운영시간, 알려진 자가용 구간 40분·도보 상한, 예산과 예약 시각의 기존 검사는 유지한다. 식당이 실제 17:30에 열거나 사용자가 17:30으로 확정한 경우에는 해당 시각을 지킨다.

기존 필수 위반 수 → 취향·카테고리·의미 점수 → 권장 식사 시간 이탈 → 이동시간 순으로 비교한다. 같은 방문 집합·적합도에서는 권장 식사 시간에 가까운 순서를 우선한다. 시각이 미확인이면 식사 시간 개선으로 간주하지 않는다. 내부 점수를 공개 DTO에 추가하지 않는다.

이번 작업은 새 장소를 추가해 빈 시간을 채우는 기능이 아니다. 적절한 대안 순서가 없으면 권장 시간대 밖의 식사도 남을 수 있다. 식사 개수·후보를 보충하는 기존 AI 패키지 처리는 유지한다.

## 적용과 확인 범위

생성 정책 버전을 올려 기존 정책의 결과를 새 결과로 재사용하지 않는다. BE 서버 재시작 후 일정을 새로 생성해야 적용된다. 기존에 저장된 일정이나 취향 확정 데이터는 수정하지 않는다.

## 실행한 검증 — 2026-11-14

- `.\.venv\Scripts\python.exe -m pytest -q -m "not mysql" -o faulthandler_timeout=30`: **369개 통과, MySQL 177개 제외**. 기존 deprecation 경고는 남아 있다.
- `.\.venv\Scripts\python.exe -m unittest discover -s ../WOOWANGTHON_TEAM_17_AI/tests`: **55개 통과**. AI 저장소는 수정하지 않았다.
- `python -m compileall -q app tests scripts run.py`, `python -m pip check`, `git diff --check`: 저장소 `.venv` 기준 통과. 별도 BE lint/typecheck는 설정되지 않았다.
- 독립 GPT-6.1 Sol high 검토의 다일차 `START` 노드 누락·식사 종료시각 감점 지적을 수정했다. 이후 미해결 P1/P2는 없으며, 독립 합성 실행에서도 실제 생성기의 식사 순서 개선을 확인했다.

기본 시각의 강제 대기 제거, 권장 구간 밖 식사 허용, 예약 시각 유지·지각 차단, 실제 개장 시각 대기, KST 변환, 2일 차의 설정 사용, 미확인 시각의 불리한 비교를 검사했다. 일반 식사의 권장 점수는 조기 시작 분수와 권장 종료 뒤 완료 분수를 더한다. 예약 식사는 이 점수에서 제외되며 기존 필수 검사가 담당한다.

| 합성 재현 | 변경 전·기준선 | 변경 후 |

| 점심 14:23 종료 + 가짜 이동시간 13분 | 다음 자동 식사 17:30, 이동 외 대기 174분 | 다음 방문 14:36, 이동 외 대기 0분 |

첫 비교는 이전 커밋 `6e367ce`와 현재 `_fit_day`에 같은 입력을 넣었다. 둘째 비교는 현재 생성기의 최적화 끄기/켜기를 비교했다. 둘째 사례는 양쪽 모두 알려진 위반 0개, 방문 수 2곳이며 최적화가 순서 변경 1회를 채택했다. 실제 사진 속 여행방을 조회하거나 갱신한 결과는 아니다. 합성 입력 2개의 기능 확인 수치를 실제 사용자 개선율로 확장하지 않는다.

전체 실행 중 기존 임베딩 시간 제한 검사의 1ms 실시간 대기가 Windows 타이머 정밀도에 따라 흔들려, 해당 검사를 격리된 가짜 시계로 안정화했다. 제품 임베딩 구현은 변경하지 않았다.

실제 사용자 평가 참여자는 0명이며 만족도는 미검증이다. 이번 작업에서 실제 여행방 생성·저장, Gemini·도로 경로 호출, 공용 DB 쓰기·스키마 변경은 실행하지 않았다. 사용자 지시에 따라 충북 전체 오류·지역 후보 로직은 변경하지 않았으며, 취향 확정·실패 안내·FE·공개 API도 변경하지 않았다.
