# 걷기 회피와 도보 제한 통합

로컬 작업 범위다. HTTP 요청·응답이나 DB 테이블을 추가하지 않고 기존 개인 원문, 회피 조건의 중요도, `walking` 선택을 함께 확인한다.

## 적용 방식

- 필수 회피 조건이 순수하게 “오래 걷는 것은 싫어요”, “긴 도보 이동”이고 도보 20분 또는 40분을 선택하면, 장소 사이 한 번의 도보 이동 제한으로 반영한다. 같은 문장을 장소 태그로 다시 검증하지 않는다.
- 필수 걷기 회피에 `제한 없음`을 선택하거나 시간이 빠지면 걷기 항목에서 보완을 안내한다. 명시한 최대 시간보다 느슨한 선택도 수정이 필요하다.
- 원문은 보존한다. 다른 장소·활동 회피 조건은 계속 검증하며, 계단·등산·접근성·하루 총 도보 시간·거리·도보 불가 조건을 구간별 시간 제한만으로 충족했다고 처리하지 않는다.
- 기존 20분/40분 경로 검증이 실제 제한을 담당한다. 장소 내부의 보행 시간이나 하루 총 보행량을 보장하는 기능은 아니다.
- 미완성 초안 저장과 준비 완료는 구분한다. 원문을 수정하거나 선택을 바꿔 충돌을 해소한 뒤 준비 완료할 수 있다. 추가 대화창은 만들지 않는다.

개인 확인 API와 일정 생성 준비 검사에도 같은 기준을 적용한다. 예전 확인 상태가 남아 있어도 충돌한 입력으로 새 일정을 생성하지 않도록 검사한다. 원문은 단체 상태나 일정 생성용 공개 입력에 추가하지 않는다.

## 로컬 확인

FE에서 `npm run build` 후 기존 8017 서버가 제공하는 `/room.html?preview=room`을 새로고침한다. 이 예시 화면은 실제 여행방에 저장하지 않는다. BE 동작은 기존 서버를 재시작한 뒤 적용된다. 생성 정책 버전 변경으로 기존 결과는 새 정책의 검증 결과로 재사용하지 않는다.

`tests/fixtures/walking_preference_cases.json`은 사람이 수집한 사용자 응답이 아닌 **합성 입력 30개**다. 같은 파일을 FE에도 복사하고 Python·TypeScript의 반환값을 기대 결과와 비교했다. 정상 20/40분, 미선택, 제한 없음, 선호/필수, 원문 20분과 선택 40분의 충돌, 더 엄격한 선택, 계단·쇼핑 혼합, 하루 총량·거리·도보 불가, 질문·부정 표현, 15분 상한 등을 포함한다. “20분 이상 걷기 회피”는 20분 이내와 경계 의미가 달라 미해결로 남긴다. 임의의 자연어를 모두 이해한다고 보장하지 않는다.

추가 SQLite 검사는 임시 DB에서 실제 준비 API 경로를 호출한다. 접근 권한 함수만 테스트 대역으로 두고, 이미 확인된 문서와 미확인 문서 각각에서 충돌 시 400, 미완성 초안 저장, 20분으로 수정 후 확인, 같은 확인 재요청, 오래된 버전의 409를 확인했다. 생성 준비도는 방장·참여자 모두 원문 상한을 검사하고 공개 토큰에 원문이 없는지 확인했다. MySQL 잠금·인증 검증을 대체하지 않는다. 기존 도보 경로 검사의 1,200초 허용·1,201초 위반 회귀 검사도 위 전체 실행에 포함된다.

브라우저는 실제 DB에 쓰지 않는 `/room.html?preview=room`에서 확인했다. 필수 “오래 걷는것은 싫어요”+20분의 반영 안내, 제한 없음의 수정 안내, 원문 최대 20분+선택 40분의 충돌, 키보드로 20분 선택 후 해결, 원문 보존을 확인했다. 기본 PC 화면과 390×844 모바일 화면에서 안내·버튼 배치를 확인하고, 안내가 버튼과 겹친 초기 문제를 간격 수정 후 재확인했다.

**미검증:** 실제 사용자 평가 참여자 0명, 만족도 미측정. 이번 작업에서 Gemini·실제 경로 제공자 호출, 공용 DB 쓰기, 실제 여행방의 전체 일정 생성은 실행하지 않았다. 합성 입력 자동 검사와 예시 UI 검수를 실제 사용자 효과로 보고하지 않는다.
