# 일정 생성: ALNS 복구와 임베딩·MMR

사용자가 요청한 생성 알고리즘의 로컬 확장이다. 취향 해석·확정과 생성 실패 안내는 이번 작업에서 변경하지 않는다. 기존 공개 API, DB 테이블·JSON 계약, FE도 유지한다.

## 적용 위치

기존 필수 조건 필터 → AI 방문 초안 → 공개 장소 설명 임베딩 → 전체 시간표 검사 → 필요하면 ALNS 복구 → 기존 2-opt/relocate/TOPTW 참고 탐색 → 최종 검증 순서다. 임베딩과 탐색은 DB 연결을 닫은 뒤 실행하고, 저장 전에 기존 입력 버전·장소 digest·권한·lease를 다시 확인한다.

ALNS는 일부 유연 방문을 함께 제거하고 적격 후보를 다시 삽입한다. 제거·복구 연산자의 성공 결과에 따라 다음 연산자 선택 가중치를 바꾼다. 단일 장소 이동으로 풀리지 않는 조합도 제한된 탐색 안에서 검토한다. 예약의 날짜·위치, 숙소의 날짜·시간·마지막 배치, 식사 날짜·개수와 전체 방문 수를 보존하며 후보 허용 날짜를 지킨다. 복구 실패 시 기존 시간표 맞춤 경로로 돌아간다. 전역 최적해나 불가능성 증명을 제공하지 않는다.

MMR은 `0.8 × 기존 적합도 - 0.2 × 이미 선택한 장소와의 최대 cosine`으로 후보 순서를 정한다. 같은 날짜의 기존 카테고리 반복 감점도 유지한다. 최종 일정 비교에서는 날짜별 각 유연 방문의 최대 양의 cosine 합계를 2로 나눈 의미 중복량에 0.2를 곱해 감점한다. 순서와 무관하며 고정 약속과 숙소는 제외한다. 임베딩 유사도는 장소 선택의 참고값이며, 도보·자가용·예약·영업시간·예산 충족을 증명하지 않는다.

## 실제 임베딩과 실패 시 동작

기본 제공자는 Gemini `gemini-embedding-2`, 출력 768차원이다. 표준 라이브러리 HTTPS로 `batchEmbedContents`를 호출하며 기존 AI 패키지의 개인 키 로더를 사용한다. 비밀키를 BE 코드·문서·산출물에 복사하지 않는다. 장소의 공개 설명만 명시적으로 추출하며 개인 원문·확정 취향·개인/단체 점수는 제공자에 전송하지 않는다.

적격 후보 최대 200개를 한 배치 최대 100개, 최대 2회, 전체 8초 이내에서 처리한다. 자동 재시도는 하지 않는다. 벡터 개수·차원·숫자·유한값·영벡터를 검사한다. 모델·차원·공개 설명 digest 기반의 제한된 메모리 캐시를 사용한다. 벡터 DB나 새 의존성은 추가하지 않는다.

전체 후보의 벡터가 없으면 해당 생성 작업의 의미 점수는 사용하지 않고 기존 카테고리 점수로 돌아간다. 일부 후보만 벡터가 없어 중복 감점을 피하는 일이 없도록 한다. 장애·미설정 상태를 임베딩 성공으로 기록하지 않는다. 테스트에서는 `app.state.generation_embedder=False`로 유료 외부 호출을 차단하거나 명시적으로 가짜 제공자를 주입한다.

## 제한과 검증

ALNS와 기존 탐색은 평가 횟수·추가 경로 조회·탐색 시간 예산을 공유한다. 전체 경로 조회 최대 64회, 탐색의 추가 경로 최대 6회, 후보 평가 최대 24회와 기존 job deadline을 유지한다. 좌표 거리나 임시 이동시간을 검증된 경로로 바꾸지 않는다. 알려진 필수 위반이 남는 복구 결과는 채택하지 않는다.

기본 초안의 검사·참조 진단은 탐색 평가 24회에 포함하지 않는다. 탐색 마감은 진입·반복에서 1초 기준으로 검사하며 네트워크 대기까지 포함한 1초 응답을 보장하는 값은 아니다. 복구가 성공하면 남은 공용 예산으로 기존 탐색을 시도하고, 그 후속 탐색에 예외가 나도 이미 재검증한 복구 결과를 유지한다. ALNS와 후속 탐색의 횟수는 내부 보고서에서 구분한다.

생성 정책 버전을 올려 이전 정책 결과를 새 결과로 재사용하지 않는다. 기존 서버를 재시작한 뒤 새로 생성해야 적용된다. 과거 일정이나 취향 확정 데이터를 수정하지 않는다.

## 실제 임베딩 연결 확인 — 2026-11-14

공개 합성 장소 설명 4개(호수 전망대, 호수 전망 카페, 도자기 공방, 역사 전시관)를 **실제 Gemini에 1배치·1회** 전송했다. `READY`, 768차원 벡터 4개를 받았고 해당 한 번의 로컬 소요 시간은 1.047초였다. 개인 원문이나 사용자 여행방·DB는 사용하지 않았다.

전망대와 전망 카페의 cosine은 0.921579, 전망대와 공방은 0.808228, 전망대와 전시관은 0.811743이었다. 이는 해당 네 문장의 모델 출력이며 정확도·만족도 백분율이 아니다. 전체 일정 품질이나 모든 장소의 의미 분류 성능을 입증하지 않는다.

오프라인 비교는 합성 입력·가짜 경로 행렬·명시적인 합성 벡터를 사용한다. 실제 제공자 연결 확인과 구분한다. 실제 사용자 평가 표본은 0명이며 만족도는 미검증이다.

## 실행한 기능 검사와 비교

- `.\.venv\Scripts\python.exe -m pytest -q -m "not mysql" -o faulthandler_timeout=30`: **357개 통과, MySQL 177개 제외**. 기존 Starlette/httpx·SQLite datetime 경고는 남아 있다.
- `.\.venv\Scripts\python.exe -m unittest discover -s ../WOOWANGTHON_TEAM_17_AI/tests`: **55개 통과**. AI 저장소 코드는 수정하지 않았다.
- `.\.venv\Scripts\python.exe -m compileall -q app tests scripts run.py`, `python -m pip check`, `git diff --check`: 통과. BE 별도 lint/typecheck는 설정돼 있지 않다.
- 독립 GPT-6.1 Sol high 검토에서 찾은 시간 예산·실패 호출 집계·MMR 계산량·식사 복원·연박 숙소·적격 후보 순서·후속 최적화 예외 문제를 수정했고, 최종 미해결 P1/P2는 없다.

`scripts/evaluate_generation_search.py`로 **합성 사례 4개 × 4조건 = 16회**를 비교했다. 모든 조건에서 기존 2-opt/relocate와 카테고리 감점을 사용하며 ALNS·의미 감점만 켜고 끈다. 손으로 작성한 초안·경로 시간·벡터를 사용하므로 Gemini 일정 생성 성능이나 실제 도로 성능을 평가한 것이 아니다.

| 합성 사례·관측값 | 기존 | ALNS만 | 의미 감점만 | 둘 다 |
| --- | --- | --- | --- | --- |
| 두 유연 장소를 함께 교체해야 하는 일정: 남긴 방문 수 / 요청 3곳 | 1 | 3 | 1 | 3 |
| 날짜 배분이 필요한 일정: 남긴 방문 수 / 요청 3곳 | 2 | 3 | 2 | 3 |
| 서로 다른 카테고리지만 의미가 비슷한 두 장소: 의미 중복량 | 1.0 | 1.0 | 0.0 | 0.0 |
| 시간상 불가능한 고정 약속 | 차단 | 차단 | 차단 | 차단 |

의미 중복 사례는 네 조건 모두 방문 수 2곳을 유지했다. 시간표를 반환한 12회 모두 알려진 제약 위반은 0개였고, 불가능한 사례는 4회 모두 차단했다. 기존 방식도 가능한 세 사례에서 시간표를 반환했으므로 이번 결과를 생성 성공률 증가로 보고하지 않는다. 복구가 방문 축소를 줄였다는 제한된 근거다. 반환한 12회는 비용·숙박 위치 등의 미확인이 남아 **모두 검증 상태 `unknown`**이었다. 반환을 ‘모든 항목 검증 완료’로 해석하지 않는다.

각 실행의 방문 ID·검증 상태·미확인 영역·의미 중복·가짜 경로 조회 수·ALNS 연산자 가중치·평가 횟수는 [전체 결과 JSON](generation-search-evaluation-results.json)에 기록한다. 이 16회에서 경로 조회 수는 최대 10회, 탐색 평가 수는 최대 24회였다. 개선율을 실제 사용자 효과로 확장하지 않는다.

MMR의 후보 200개 검사에서는 벡터 쌍별 cosine을 한 번만 계산하는지 확인했다. 같은 로컬 합성 벡터로 관측한 전체 200개 순위는 0.219초, 상위 8개 순위는 0.031초였다. 이는 단일 실행의 함수 검사이며 서버 응답시간 보장이나 실제 임베딩 품질 지표가 아니다.

**미실행·미검증:** 전용 MySQL 통합, 실제 도로 경로 조회, 실제 여행방의 전체 생성·저장, 사람의 만족도 평가. 공용 DB 쓰기·스키마 변경·외부 문서 수정·원격 push는 하지 않았다. FE 변경이 없어 FE 빌드·브라우저 검수는 이 작업에서 실행하지 않았다.
